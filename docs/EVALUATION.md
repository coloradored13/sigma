# Outcome evaluation plan

Keep engineering acceptance tests separate from outcome evidence. None of the
current tests establishes that Sigma Public produces better analyses or builds.

Pilot task families separately: grounded analysis, defect review (including clean
repositories), and implementation/repair with hidden behavioral acceptance tests.
Prospective forecasts need immutable predictions, event definitions, information
cutoffs, resolution sources, close dates, and void rules before scoring.

Compare a capable single session, self-critique, targeted independent verifier,
independent non-debating ensemble, and a bounded adversarial configuration. Evaluate
realistic defaults and matched budgets with comparable evidence/tools. Record model,
prompt, tool and source versions, latency, all calls/retries, completion and failure
rates, cost, human intervention and correct answers made worse by criticism.

Use 30–50 tasks as a pilot to estimate variance, then size held-out evaluations for
a predeclared useful effect. Repeat runs without confusing repetitions with new
independent tasks. Reset memory between unrelated items; evaluate cross-task learning
as a separate controlled experiment. Blind and randomize human grading, verify
citations and decision-critical claims, and validate model judges on held-out human
labels. Do not use answer preference or process compliance as sole ground truth.

For builds, execute hidden acceptance and existing regression tests against the
final tree. Measure introduced defects as well as detected defects. Correctness and
authorization failures block release instead of being offset by style scores.
For verifiers, report precision/recall, abstention, false reassurance, and downstream
answer improvement. For continuous forecasts, choose a proper interval score or a
declared predictive distribution; a point and range do not define a log likelihood.

Ablate mechanism bundles and important interactions. Keep security/correctness
invariants justified by their failure tests. Choose the default from demonstrated
task-specific benefits. Neither adversarial debate nor this smaller architecture is
assumed superior before measurements exist.
